## g2-01 GAN（敵対的生成ネットワーク）

**問題**: 生成器（Generator）と識別器（Discriminator）を競わせて学習する生成モデルはどれ？
選択肢: (0)GAN（正解） / (1)RNN / (2)決定木 / (3)k近傍法

### 事実

- **GAN（敵対的生成ネットワーク）**: Ian Goodfellow らが2014年に発表した論文「Generative Adversarial Networks」で提案。生成モデルGと識別モデルDを同時に学習させる枠組みで、Gはデータ分布を捉えようとし、Dはサンプルが訓練データ由来か生成モデルG由来かを判定する確率を推定する。両者はミニマックス（minimax）の二人零和ゲームに相当し、多層パーセプトロンで構成する場合は誤差逆伝播法のみで学習でき、マルコフ連鎖や近似推論ネットワークの展開が不要という利点がある。
  - 出典: [arXiv:1406.2661「Generative Adversarial Networks」](https://arxiv.org/abs/1406.2661)（2014年6月10日投稿、著者: Ian J. Goodfellow, Jean Pouget-Abadie, Mehdi Mirza, Bing Xu, David Warde-Farley, Sherjil Ozair, Aaron Courville, Yoshua Bengio）
  - 確度: 高（原論文で確認）
  - GUGAシラバス第2章の詳細キーワードにも「GAN（敵対的生成ネットワーク）、生成器、識別器」として明記。

- **RNN（回帰型ニューラルネットワーク、Recurrent Neural Network）**: 隠れ層の出力を次の時刻の入力にフィードバックする構造を持ち、時系列データや自然言語など系列データの処理に用いられる。ノード間の結合がループ（自己回帰的な有向グラフ）を持つ点が通常のニューラルネットワークと異なる。「生成器と識別器の競争」という学習の仕組みはRNN自体には存在しない。
  - 出典: GUGAシラバス第2章詳細キーワード（RNN、隠れ層、リカレント層、シーケンスデータ）。技術的な定義は複数の学術解説で一致（確度：中〜高。原著論文個別の直接確認はしていないが、シラバス上の位置づけは一次資料で確認済み）。
  - 確度: 高（シラバスでの位置づけ）／中（技術定義の細部）

- **決定木（Decision Tree）**: Googleの機械学習用語集では「条件（condition）」と「葉（leaf）」から階層的に構成される教師あり学習モデルと定義される。各非葉ノードが条件（分岐）を持ち、各葉ノードが予測値を持つ。ルート（根）から葉までの経路をたどって予測を行う、GANのような敵対的な学習プロセスとは無関係の手法。
  - 出典: [Google Machine Learning Glossary: Decision Forests](https://developers.google.com/machine-learning/glossary/df)
  - 確度: 高（Google公式の用語集）

- **k近傍法（k-Nearest Neighbors, k-NN）**: 分類したいデータ点に対して、学習データの中から距離が近いk個の近傍点を探し、多数決（または平均）で予測するノンパラメトリックな手法。理論的基礎は Cover と Hart の1967年の論文「Nearest neighbor pattern classification」（IEEE Transactions on Information Theory, Vol.13(1), pp.21-27）で確立され、k-NN則の誤り率がベイズ誤り率の2倍以下に抑えられることなどが示された。
  - 出典: [Cover & Hart (1967) 原論文PDF（Stanford ISL）](https://isl.stanford.edu/~cover/papers/transIT/0021cove.pdf)
  - 確度: 高（原論文の存在・内容を確認）

### 出題の狙い（想定される引っかけ）
- GAN（生成器と識別器が競う＝敵対的学習）とRNN（系列データを扱うが、敵対的学習ではない）を、「複雑な生成モデル」という漠然としたイメージで混同させる。
- 決定木・k近傍法は生成AIと無関係な古典的な教師あり学習手法であり、「AIの手法」という共通点だけで誤答を選ばせる引っかけ。

## g2-02 Transformer

**問題**: 2017年に発表され、現在の大規模言語モデルの土台となったモデル構造はどれ？
選択肢: (0)Transformer（正解） / (1)CNN / (2)GAN / (3)オートエンコーダ

### 事実

- **Transformer**: Ashish Vaswani ほか（Google Brain / Google Research）が2017年に発表した論文「Attention Is All You Need」（arXiv:1706.03762）で提案。再帰（recurrence）や畳み込み（convolution）を一切使わず、Attention機構のみに基づく新しいネットワークアーキテクチャ。機械翻訳タスクで高品質かつ並列化しやすく学習時間も大幅に短いことを示した。NeurIPS 2017（2017年12月4〜9日、Long Beach, CA）で発表。BERT（2018）、GPT-2・GPT-3など、後続の多くの言語モデルの基盤となった。
  - 出典: [arXiv:1706.03762](https://arxiv.org/abs/1706.03762)
  - 確度: 高（原論文で確認）

- **CNN（畳み込みニューラルネットワーク）**: Yann LeCun ほかによる1998年の論文「Gradient-based learning applied to document recognition」（Proceedings of the IEEE, Vol.86, No.11, pp.2278-2324）で、勾配降下法によるエンドツーエンド学習が可能なCNNが手書き文字認識（郵便番号）に適用され、当時の他手法を上回る性能を示した。Transformerより約19年前に発表された、主に画像処理向けのアーキテクチャ。
  - 出典: LeCun, Bottou, Bengio, Haffner (1998), IEEE Xplore doi:10.1109/5.726791
  - 確度: 高（学術誌掲載情報として確認。全文の直接取得はできていないが書誌情報は複数の学術ソースで一致）

- **GAN（敵対的生成ネットワーク）**: g2-01参照。2014年発表で、Transformerより3年早い。

- **オートエンコーダ（Autoencoder）**: 入力を低次元の潜在表現に圧縮するエンコーダと、そこから入力を復元しようとするデコーダから構成されるニューラルネットワーク。深層オートエンコーダによる次元削減を示した代表的研究として、Geoffrey Hinton と Ruslan Salakhutdinov の2006年の論文「Reducing the Dimensionality of Data with Neural Networks」（Science, Vol.313, pp.504-507）があり、主成分分析（PCA）より優れた次元削減ツールとなることを示した。Transformerより11年早い。
  - 出典: [Hinton & Salakhutdinov (2006) PDF（トロント大学）](https://www.cs.toronto.edu/~hinton/absps/science.pdf)、DOI: 10.1126/science.1127647
  - 確度: 高（一次資料、全文確認済み）

### 出題の狙い（想定される引っかけ）
- 「2017年」「LLMの土台」という2条件を正しく満たすのはTransformerのみ。CNN・GAN・オートエンコーダはいずれもTransformerより前に発表された別系統の技術であり、発表年を正確に覚えていないと混同しやすい。

## g2-03 GPT（Generative Pre-trained Transformer）

**問題**: 「GPT」の正式名称として正しいものはどれ？
選択肢: (0)Generative Pre-trained Transformer（正解） / (1)General Purpose Technology / (2)Global Prompt Tool / (3)Generated Picture Translator

### 事実

- **GPT = Generative Pre-trained Transformer**: OpenAIのAlec Radford, Karthik Narasimhan, Tim Salimans, Ilya Sutskever による2018年の技術レポート「Improving Language Understanding by Generative Pre-Training」で初めて提案されたモデル（後にGPT-1と呼ばれる）。ラベルなしの大規模テキストコーパスで生成的な事前学習（generative pre-training）を行い、各タスクに応じて識別的にファインチューニングするという手法で、12層のデコーダのみのTransformer（768次元・12アテンションヘッド）を用いる。
  - 出典: [OpenAI公式PDF「Improving Language Understanding by Generative Pre-Training」](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf)、[OpenAI公式サイトの紹介記事](https://openai.com/index/language-unsupervised/)
  - 確度: 高（一次資料、OpenAI公式）
  - GUGAシラバス第2章にも「GPTモデル、Open AI」「GPT-1」が明記されている。

- **誤答②「General Purpose Technology（汎用技術）」**: これは架空の語ではなく、**実在する経済学の用語**（日本語では「汎用技術」）。Timothy Bresnahan と Manuel Trajtenberg が1995年の論文「General Purpose Technologies 'Engines of Growth?'」（Journal of Econometrics, Vol.65, pp.83-108／NBER Working Paper No.4148）で提唱した概念で、蒸気機関・電動機・半導体・コンピュータのように、経済全体に広く波及し（pervasiveness）、技術的に改良され続け（技術改善の余地）、下流産業のイノベーションを誘発する（innovational complementarities）技術群を指す。GPT（Generative Pre-trained Transformer）とは全く別の概念だが、頭文字が同じ「GPT」になる点が紛らわしい。
  - 出典: [NBER Working Paper No.4148](https://www.nber.org/papers/w4148)、[原論文PDF（著者サイト）](https://tbres.su.domains/wp-content/uploads/2023/11/Bresnahan-and-Trajtenberg-1995-General-purpose-technologies-%E2%80%98Engines-of-growth.pdf)
  - 確度: 高（一次資料相当のNBER・著者公開PDFで確認）

- **誤答③④「Global Prompt Tool」「Generated Picture Translator」**: OpenAI公式資料・経済学文献のいずれにもこれらが正式名称・専門用語として使われている用例は見当たらなかった。作問上の架空の語（ダミー選択肢）と判断してよい。
  - 確度: 高（OpenAI一次資料に存在しないことを確認した限りでの消去法。「世界のどこにも存在しない」という完全な悉皆調査はしていない）

### 出題の狙い（想定される引っかけ）
- 「General Purpose Technology」は完全な架空語ではなく実在する経済学用語（略しても「GPT」になる）である点が、他の2つの架空選択肢よりはるかに紛らわしい。「GPTの正式名称」という問いに対し、AIのGPTと経済学のGPTを取り違えさせる高度な引っかけになっている。

## g2-04 ハルシネーション

**問題**: 生成AIが事実と異なる内容を、もっともらしく出力してしまう現象はどれ？
選択肢: (0)ハルシネーション（正解） / (1)過学習 / (2)バイアス / (3)ディープフェイク

### 事実

- **ハルシネーション**: OpenAIの研究者（Adam Tauman Kalai, Ofir Nachum, Santosh Vempala, Edwin Zhang）による2025年9月5日公開の論文「Why Language Models Hallucinate」では、言語モデルが誤りを堂々と生成する現象の統計的な原因を分析し、標準的な学習・評価手法が「不確実性を認めること」より「推測（guessing）」に報酬を与えてしまうことが一因だと論じている。生成が分類より難しいタスクであるため、真偽を正しく分類できるモデルでも、直接生成させると誤りを生んでしまう、という論点を提示している。
  - 出典: [OpenAI公式ページ「Why language models hallucinate」](https://openai.com/index/why-language-models-hallucinate/)、[論文PDF](https://cdn.openai.com/pdf/d04913be-3f6f-4d2b-b283-ff432ef4aaa5/why-language-models-hallucinate.pdf)
  - 確度: 高（OpenAI公式の一次資料、2026年9月時点で直近1年以内の発表）
  - GUGAシラバス第2章にも「ハルシネーション（Hallucination）」が明記。

- **過学習（オーバーフィッティング）**: Googleの機械学習用語集では「モデルが訓練データに過度に一致してしまい、新しいデータに対して正しい予測ができなくなる状態を作ること」と定義される。これは学習プロセス上の問題であり、「もっともらしい誤り」という出力内容の現象そのものを指す語ではない。GUGAシラバス第1章にも「過学習」「過学習を避ける手法」として明記されている（第1章の学習項目であり、第2章のハルシネーションとは章が異なる点に注意）。
  - 出典: [Google Machine Learning Glossary: ML Fundamentals](https://developers.google.com/machine-learning/glossary/fundamentals)
  - 確度: 高

- **バイアス**: AIモデルが学習データに含まれる偏り（性別・人種等）を反映し、出力が特定の方向に偏る現象。ハルシネーション（事実と異なる内容の捏造）とは異なる問題であり、「偏り」と「誤り」を区別する必要がある。
  - 確度: 中（一般的なAI倫理の文脈での定義。今回は特定の一次資料への直接引用はできていない）

- **ディープフェイク**: g2-05・第4章g4-08の研究メモで確認済み。実在の人物の顔・声を合成した偽の映像・音声を作る技術・生成物を指し、「事実と異なるテキストの生成」とは異なるモダリティ・現象。
  - 確度: 高（第4章メモで確認済み、総務省資料に基づく）

### 出題の狙い（想定される引っかけ）
- 「過学習」は第1章キーワード、「ハルシネーション」は第2章キーワードと、GUGAシラバス上も別の章に位置づけられている。「AIの失敗に関する用語」という共通点だけで両者を混同しやすい。
- バイアス（偏り）とハルシネーション（事実の捏造）は、どちらも「AIの問題点」として語られがちだが、原因も現象も異なる。

## g2-06 Sora（OpenAIの動画生成AI）※重要な現状確認あり

**問題**: OpenAIが提供する、テキストから動画を生成するAIはどれ？
選択肢: (0)Sora（正解） / (1)DALL-E / (2)Whisper / (3)Codex

### 事実

- **Sora**: OpenAIが開発したテキストから動画を生成するAIモデル。2024年12月に一般提供開始。2025年9月末には「Sora 2」が米国・カナダの一部ユーザー向けに提供開始された。GUGAシラバス第2章にも「Sora」がキーワードとして明記されており、2025年10月1日の改訂で追加された論点である。

## g2-07 トークン

**問題**: 大規模言語モデルがテキストを処理するときの、単語や文字の断片にあたる単位を何という？
選択肢: (0)トークン（正解） / (1)パラメータ / (2)エポック / (3)バッチ

### 事実

- **トークン（Token）**: Googleの機械学習用語集（言語分野）では「言語モデルが処理するテキストの単位。トークンは単語、単語の一部、あるいは句読点のような文字だけの場合もある。一般にトークンは文字の並びで構成される。例えば『tokenization』という単語は『token』と『ization』というトークンに分割されることがある」と定義される。
  - 出典: [Google Machine Learning Glossary: Language](https://developers.google.com/machine-learning/glossary/language)
  - 確度: 高（Google公式の用語集）

- **パラメータ（Parameter）**: Googleの機械学習用語集（基礎編）では「モデルが学習中に学習する重み（weights）とバイアス（biases）」と定義される。GUGAシラバス第2章にも「GPT-2、パラメータ」として明記されている。トークンが入力テキストの単位であるのに対し、パラメータはモデル自体が内部に持つ学習可能な数値であり、両者は全く異なるレイヤーの概念。
  - 出典: [Google Machine Learning Glossary: ML Fundamentals](https://developers.google.com/machine-learning/glossary/fundamentals)
  - 確度: 高

- **エポック（Epoch）**: Googleの機械学習用語集では「訓練セット全体を1回処理し終える、完全な1回の学習パス。各サンプルが1回ずつ処理された状態を指す」と定義される。学習の反復回数の単位であり、テキストの分割単位（トークン）とは無関係。
  - 出典: 同上
  - 確度: 高

- **バッチ（Batch）**: Googleの機械学習用語集では「1回の学習イテレーションで使われるサンプルの集合。バッチサイズがバッチに含まれるサンプル数を決める」と定義される。こちらも学習プロセス上の単位であり、テキストの分割単位ではない。
  - 出典: 同上
  - 確度: 高

### 出題の狙い（想定される引っかけ）
- 「トークン」（テキストの処理単位）と「パラメータ」（モデルの学習可能な重み）はどちらもLLMの文脈でよく登場する数値（例：「◯◯億パラメータ」「入力は◯万トークンまで」）だが、指している対象が全く異なる点を混同しやすい。
- エポック・バッチは学習プロセスの単位であり、いずれも「テキストの分割単位」ではない。3つとも機械学習の基礎用語である点で、正確な定義の理解が必要。

## g2-08 拡散モデル（Diffusion Model）

**問題**: 画像にノイズを加える過程を逆にたどり、ノイズを除去しながら画像を生成するモデルはどれ？
選択肢: (0)拡散モデル（正解） / (1)GAN / (2)VAE / (3)RNN

### 事実

- **拡散モデル（Diffusion Model）**: Jonathan Ho, Ajay Jain, Pieter Abbeel による2020年の論文「Denoising Diffusion Probabilistic Models」（DDPM、arXiv:2006.11239）で、高品質な画像生成を実現する潜在変数モデルの一種として提案された。データに徐々にノイズを加えていく拡散過程（forward process）と、その逆をたどってノイズを除去していく逆拡散過程（reverse process）を学習することで、ノイズからデータ分布に従うサンプルを生成する。Stable Diffusion等、現在主流の画像生成AIの多くがこの拡散モデルの系譜にある。
  - 出典: [arXiv:2006.11239](https://arxiv.org/abs/2006.11239)、[著者公式GitHub](https://github.com/hojonathanho/diffusion)
  - 確度: 高（原論文の存在・内容を確認）

- **GAN**: g2-01参照。生成器と識別器の敵対的学習によりデータを生成する枠組みで、ノイズ除去の逐次過程は用いない。

- **VAE（変分自己符号化器、Variational Autoencoder）**: Diederik P. Kingma と Max Welling による2013年の論文「Auto-Encoding Variational Bayes」（arXiv:1312.6114）で提案された、確率的な変分推論に基づく学習アルゴリズム（Auto-Encoding Variational Bayes, AEVB）。エンコーダが入力を潜在変数の確率分布（平均・分散）に変換し、デコーダがそこからサンプリングして入力を復元しようとする構造。GUGAシラバス第2章にも「VAE（変分自己符号化器）、ノイズ、エンコーダ、デコーダ、潜在ベクトル」として明記されている。ノイズを加えて除去する反復過程（拡散過程）ではなく、1回のエンコード・デコードで潜在表現を扱う点が拡散モデルと異なる。
  - 出典: [arXiv:1312.6114](https://arxiv.org/abs/1312.6114)
  - 確度: 高（原論文の存在・内容を確認）

- **RNN**: g2-01参照。系列データを扱うためのアーキテクチャであり、画像のノイズ除去による生成プロセスとは無関係。

### 出題の狙い（想定される引っかけ）
- VAEも「ノイズ」「エンコーダ」「デコーダ」といった語彙を共有するためシラバス上も拡散モデルと混同しやすいが、VAEは1回の符号化・復号、拡散モデルは多段階のノイズ除去過程という違いがある。
- GANも生成モデルの一種だが、ノイズ除去ではなく敵対的な学習によって生成する点が拡散モデルと異なる。

## g2-09 マルチモーダルAI

**問題**: テキスト・画像・音声など、複数の種類のデータを組み合わせて扱えるAIを何という？
選択肢: (0)マルチモーダルAI（正解） / (1)シングルタスクAI / (2)エキスパートシステム / (3)ルールベースAI

### 事実

- **マルチモーダルAI**: Google DeepMindは、自社のGeminiモデルについて「テキスト、コード、音声、画像、動画といった異なる種類の情報を一般化し、シームレスに理解・操作・統合できる」ことを「マルチモーダル」と説明している。GUGAシラバス第2章にも「マルチモーダル」がChatGPT関連のキーワードとして明記されている。
  - 出典: [Google公式ブログ「Introducing Gemini」](https://blog.google/technology/ai/google-gemini-ai/)
  - 確度: 高（Google公式の一次資料）

- **エキスパートシステム**: 特定分野の専門知識を「if-thenルール」の形で大量に蓄積し、専門家に近い推論・判断を行わせるAI。代表例として、スタンフォード大学で1965年にFeigenbaumとLederbergが開発を始めたDENDRAL（有機化合物の分子構造をマススペクトルデータから推定）や、Edward Shortliffeが1972〜1980年に開発したMYCIN（感染症の診断・抗生物質の推奨、約600の"if-then"ルールで構成、専門医に匹敵する約65%の正診率）がある。GUGAシラバス第1章「AIの歴史」にも「エキスパートシステム」が第二次AIブームの文脈で明記されている。
  - 出典: 複数の学術・大学資料（DENDRAL: [Stanford資料](https://stacks.stanford.edu/file/druid:pj337tr4694/pj337tr4694.pdf)、MYCIN: [Shortliffeらの原著書籍の序文PDF](https://www.shortliffe.net/Buchanan-Shortliffe-1984/Newell-foreword.pdf)）
  - 確度: 中〜高（MYCIN・DENDRALの歴史的事実は複数の学術資料で一致しているが、精度65%等の具体的な数値は二次的な要約記事経由の確認であり、一次資料（Shortliffeの博士論文本体等）への直接アクセスはできていない）

- **ルールベースAI**: あらかじめ人間が定義した「ルール（条件分岐）」に従って動作するAI。GUGAシラバス第1章にも「ルールベース」が「知能をもたらす2つの仕組み」の1つ（機械学習と対比される仕組み）として明記されている。エキスパートシステムはルールベースAIの一種・代表例と位置づけられる。
  - 出典: GUGAシラバスPDF第1章
  - 確度: 高

- **シングルタスクAI**: 特定の単一タスクのみに特化したAIを指す一般的な呼称（例: 画像分類専用AI、将棋AI等）。マルチモーダルAI（複数種類のデータを扱う）と対比される概念として、複数のデータ種別を扱えない・扱うタスクが1つに限定されるAIを指す文脈で使われる。GUGAシラバスの詳細キーワードには明示的な記載はないが、一般的なAI用語として広く使われている。
  - 確度: 中（シラバス上の明記はなく、一般的な用語法に基づく）

### 出題の狙い（想定される引っかけ）
- 「エキスパートシステム」「ルールベースAI」はいずれも「複数の知識・ルールを扱う」という点でマルチモーダルAI（複数種類のデータを扱う）と字面上混同されやすいが、前者は「専門知識のルール化」、後者は「入出力のデータ形式（テキスト・画像・音声等）の多様性」という全く異なる軸の話である。
- 「シングルタスクAI」はマルチモーダルAIの対義語的に使われがちだが、「タスクの数」と「扱えるデータ形式（モダリティ）の数」は本来別の軸である点に注意（マルチタスクだが単一モダリティのAI、逆にマルチモーダルだが単一タスクのAIもありうる）。

## g2-10 ファインチューニング

**問題**: 事前学習済みのモデルに、特定の用途向けのデータで追加学習させることを何という？
選択肢: (0)ファインチューニング（正解） / (1)プロンプトエンジニアリング / (2)アノテーション / (3)スクレイピング

### 事実

- **ファインチューニング（Fine-tuning）**: Googleの機械学習用語集では「事前学習済みのモデルを取り、特定のタスクやアプリケーション向けに適応させるため、新しいデータでさらに学習させること。このプロセスは、対象のユースケースに関連するラベル付きの例を使ってモデルの重みを調整する」と定義される。OpenAI公式ドキュメントでも「特定の学習データに合わせてモデルを調整するプロセス」と説明されている。GUGAシラバス第2章にも「ファインチューニング」がChatGPT関連のキーワードとして明記されている。
  - 出典: [Google Machine Learning Glossary: Language](https://developers.google.com/machine-learning/glossary/language)、[OpenAI Developers「Fine-tuning」](https://developers.openai.com/learn/fine-tuning)
  - 確度: 高（Google・OpenAIそれぞれの公式資料で確認）

- **プロンプトエンジニアリング（Prompt Engineering）**: Googleの機械学習用語集では「言語モデルから望む出力を引き出すために、入力テキスト（プロンプト）を注意深く設計すること。Chain-of-Thoughtプロンプティングのような技法は、段階的な推論を促して応答の質や精度を高める」と定義される。モデル自体の重みを更新するファインチューニングとは異なり、モデルは変更せず入力（指示文）の工夫だけで挙動を制御する手法。GUGAシラバス第5章の主題そのものでもある。
  - 出典: 同上（Google Machine Learning Glossary: Language）
  - 確度: 高

- **アノテーション（データアノテーション）**: データセットに関連するメタデータのラベル・タグを付与し、機械がデータをその意図通りに解釈できるようにするプロセス。例えば、ある画素の集合が「自転車」の画像であることや、ある文構造が数式として解釈されるべきことをモデルに伝える。教師あり学習用のデータを作る前段階の作業であり、モデル自体を学習させる「ファインチューニング」とは異なる、データ準備の工程。
  - 出典: 複数の業界解説（IBM系・データアノテーションベンダーの解説記事が一致）
  - 確度: 中（今回、特定の一次資料への直接引用はできていない。一般的な業界用語としての定義）

- **スクレイピング（Webスクレイピング）**: IBMは「AIスクレイピング」を「AIを用いてウェブサイトからのデータ抽出を自動化し、手作業より効率的・高度にデータを収集・処理するプロセス」と説明する。より広義には、ブラウザを使う人間やAPIを介したプログラム以外の手段で、インターネットから自動的にデータを収集する行為全般を指す。データを「集める」工程であり、モデルを「学習させる」ファインチューニングとは工程が異なる。
  - 出典: [IBM「What is AI Scraping?」](https://www.ibm.com/think/topics/ai-scraping)
  - 確度: 中（IBMの解説記事に基づく。学術的な一次資料ではない）

### 既存問題の確認結果
- 既存のe「汎用モデルを特定分野に合わせて調整する手法です。RAGとの違い（外部データを検索するか、モデル自体を学習し直すか）もよく問われます。」は事実として正しい記述。

### 出題の狙い（想定される引っかけ）
- ファインチューニング（モデルの重みそのものを再学習する）とプロンプトエンジニアリング（モデルは変えず入力の工夫で対応する）は、どちらも「モデルを目的に合わせて調整する」ような字面のイメージがあるが、モデル内部を変更するかどうかが決定的に異なる。
- アノテーション（データに正解ラベルを付ける準備作業）・スクレイピング（データを収集する作業）は、いずれも「モデルの学習」そのものではなく、学習の前段階・材料集めの工程である点で、ファインチューニング（学習という行為そのもの）と区別する必要がある。
