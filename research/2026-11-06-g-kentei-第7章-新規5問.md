### 論点 6. Web API（HTTP でサービスの機能を呼び出す）とステートレス

- **論点**: Web API
- **章**: 第7章 中項目 35
- **事実**:
  - Microsoft Learn の Web API 設計ガイド（Azure Architecture Center）は、REST の原則に沿った Web API を「クライアントとサービスの間の、ステートレスで疎結合なインターフェースを実現する Web API」と説明し、標準の HTTP プロトコルで、リソースに対する操作を行い、リソースの表現を返す、と述べる。原則として、(1) プラットフォーム非依存（内部実装に関係なく、クライアントが呼び出せる。標準プロトコルとして HTTP、JSON や XML などの一般的なデータ形式を使う）、(2) 疎結合（クライアントとサービスが独立して発展できる）。HTTP の動詞（GET、POST、PUT、PATCH、DELETE）で操作を表す。
  - REST の提唱者 Fielding の博士論文（第5章）は、ステートレスの制約を、「クライアントからサーバーへの各リクエストは、リクエストを理解するのに必要なすべての情報を含まなければならない」「サーバー側に保存された文脈を利用できない」「セッションの状態は、完全にクライアント側に保持される」と述べる。
  - MDN の HTTP の概要は、「HTTP はステートレス。同じ接続で連続する2つのリクエストの間に関連はない」「クッキーを使えば、ステートフルなセッションも可能」と述べる。HTTP はクライアント・サーバー型で、リクエストは常にクライアントが始め、サーバーがレスポンスを返す。
- **出典**:
  - https://learn.microsoft.com/en-us/azure/architecture/best-practices/api-design 2026-11-06（本文確認。ページ全体を取得し、冒頭部分を確認）
  - https://ics.uci.edu/~fielding/pubs/dissertation/rest_arch_style.htm 2026-11-06（5.1.2、5.1.3 を確認）
